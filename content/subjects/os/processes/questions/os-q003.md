## Answer

A zombie is an exited child whose exit information has not yet been reaped. It
does not execute or retain its ordinary user address space, but kernel bookkeeping
and a process-table/PID slot remain. An orphan is a child whose parent exited
first; the child may still be running. On Linux, adoption can involve a child
subreaper or the relevant PID namespace's init process, not necessarily the host's
PID 1 or systemd. These describe different lifecycle events, not interchangeable
names for a dead process.

### Supporting reasoning

The parent normally uses a wait-family operation to collect child exit status.
Until that information is collected, an exited child can remain a zombie.
Accumulating zombies consumes kernel bookkeeping/PID slots even though they use
no execution time and no ordinary user address space.

If a parent exits while its child is alive, reparenting changes who is responsible
for collecting the child's eventual exit information. Container supervision and
PID namespaces make the adopting process an important operational detail.

### Qualifications and common mistakes

Do not say zombies consume “no memory”: kernel records remain. Sending `kill -9`
to a zombie does not reap it because execution has already ended. Fix the parent's
reaping logic or provide appropriate supervision; killing a parent is not a
universal operational recommendation.

An orphan is not automatically dead, and adoption is not always by the host's
PID 1/systemd. A supervisor must perform the required reaping behavior.
